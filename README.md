本リポジトリのnextブランチは、[mainブランチ](https://github.com/nakano89/digital-twin-backend)と以下の点で異なります。nextブランチについて詳細を把握するためには、これに対応するクライアント実装例として、[Pyxelクライアント（バックエンドサーバー検証用）のnextブランチ](https://github.com/nakano89/digital-twin-pyxel-client/tree/next)におけるソースコードも参照してください。

* 各プレイヤーが、SFC内にいるか否かについても、扱います。
    * ①オープニング・ハンドシェイクにおいて、`digitaltwin-user-insfc`ヘッダの値（文字列）を、`true`または`false`としてください。
    * SFC Wi-Fi接続者ならSFC内にいるものとして扱う（`true`とする）といった運用を想定しています。
    * ②本サーバーからの送信において、各プレイヤーがSFC内にいるか否かの情報は`insfc`（boolean型）として含まれます。
    * この情報は、クライアントにおいて自由に活用できるほか、本サーバーにおいてもスコアの計算に活用される可能性があります（後述）。
* ビジター・プレイヤーの速度（角度と速さ）についても、扱います。
    * ②本サーバーからの送信において、各ビジターと各プレイヤーの速度が`angle`と`speed`として含まれます。
    * 角度は、北向きを0°とし、時計回りで度数が増えます。
        * 本サーバーから送信される角度は、-180°以上180°未満となりますが、クライアントから送信する角度はこの範囲に収まっている必要はありません。
        * 本サーバーはクライアントから送信された角度を、そのまま全クライアントに送信します。
    * 速さは、単位をm/sとします。
    * クライアントは、①オープニング・ハンドシェイクにおいて、`digitaltwin-user-angle`ヘッダと`digitaltwin-user-speed`ヘッダにより、速度を送信します。
    * また、③クライアントからの送信において、`angle`と`speed`として速度が含まれます。
    * 本サーバーは、位置と速度が整合しているかといった検証は行いません。
* タッチの概念は、HPの減少へと置き換えられています。
    * 各ビジターは、HP（整数であり、100からスタートし、0が下限で、回復しない）を有します。
    * クライアントは、本サーバーに対して、各ビジターへのタッチについて報告する代わりに、各ビジターのHP減少（整数）を報告します。
    * この報告は、③クライアントからの送信において`decreased_visitors_hp`により実施されます。
    * 各プレイヤーは、各ビジターのHPを減少させるたびに、これと同じだけスコアが増えます。
    * スコアの増加については、mainブランチ同様に、ビジターの現存判定と排他処理を行っています。
    * ②本サーバーからの送信において、各ビジターのHPが`hp`として含まれます。
    * 以上の変更に伴い、②本サーバーからの送信において、mainブランチの`untouched_visitors`と`touched_visitors`は、`visitors`へと統合されました。
* プレイヤーも、HPを有し、他プレイヤーからHPの減少を受けます（いわばプレイヤーへのタッチが実装されました）。
    * 各プレイヤーのHPも、整数であり、100からスタートし、0が下限で、回復しません。
    * 他プレイヤーに対するHP減少については、③クライアントからの送信において`decreased_visitors_hp`により報告されます。
    * このほか、上記ビジターのHPと同様です。
* スコアは、ビジター・他プレイヤーに対するHP減少によって同じだけ増加しますが、これに限られません。
    * スコアについては、ゲームのコンセプトを達成できるように、様々な要素を考慮して本サーバーの実装を調整していく予定です。
    * プレイヤーをSFC内外でチーム分けして、チーム全体の成績を、各プレイヤーのスコアに反映させることなどを検討しています。
    * あくまで現時点では、SFC内のプレイヤーのみに対して、30秒おきに、`( 過去30秒間にHPが0になったビジターの数 ÷ 過去30秒間に1秒以上存在したビジターの数 ) × 100`（切り捨て）が加算されます。
        * ただし、`過去30秒間に1秒以上存在したビジターの数`が0になる場合は、これを1として計算します。
    * クライアントの実装にあたっては、本サーバーがどのようにスコアを算出したとしても問題ないようにしてください。
* ダミーデータ使用時は、ダミーデータが一周するたびに、ビジターのHPが100に回復します。
